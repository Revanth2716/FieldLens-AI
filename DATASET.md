# Dataset — PlantVillage (12-class subset)

## Source

| Field | Value |
|---|---|
| Dataset | `mohanty/PlantVillage` (Hugging Face) |
| Config | `color` |
| License | **CC-BY-SA-3.0** (verified from the HF API tag *and* the upstream loader script) |
| Repository | https://github.com/spMohanty/PlantVillage-Dataset |
| Original paper | Mohanty, Hughes & Salathé (2016), *Using Deep Learning for Image-Based Plant Disease Detection*, Frontiers in Plant Science 7:1419, DOI 10.3389/fpls.2016.01419 |
| Full size | 54,305 images, 38 classes, 14 crops, 26 diseases |

The image payload is a **single 2.18 GB `data.zip`** (2,184,723,441 bytes,
163,034 members). The upstream loader calls `download_and_extract` on it, so
there is **no streaming path**: `load_dataset(...)` means the full transfer.

## License obligations

CC-BY-SA-3.0 is a **share-alike** license. Consequently:

- The dataset is **not redistributed** in this repository. `data/` is gitignored.
- Attribution is given in [ATTRIBUTION.md](ATTRIBUTION.md), the README, and the UI.
- Test fixtures are **procedurally generated** synthetic images, not dataset
  crops, so no dataset content is redistributed through the test suite.
- Split manifests are generated by a committed command rather than vendored.
  Their provenance is recorded as SHA-256 checksums of the upstream files:


- Trained weights are **not** committed by default; a one-command trainer
  reproduces them. Whether share-alike applies to model weights is legally
  unsettled, so the conservative path is taken rather than assumed.

## Classes used (12)

Four crops × two diseases + healthy, chosen so the confusion matrix is
informative rather than a diagonal — it deliberately includes the genuinely
confusable Early/Late blight pairs.

| Crop | Classes |
|---|---|
| Corn (maize) | Cercospora/Gray leaf spot, Common rust, healthy |
| Grape | Black rot, Esca (Black measles), healthy |
| Potato | Early blight, Late blight, healthy |
| Tomato | Early blight, Late blight, healthy |

## Splitting strategy

- The official **test** list (2,454 entries for these classes) is held untouched.
- Train/validation are carved from the official train list **by leaf identity**,
  never by image: 8,942 train / 1,104 validation.
- `leaf_id` is the lowercased text after `___` in the filename
  (`...___Mary_HL 9155.JPG` → `mary_hl 9155`), matching the upstream leaf map's
  own key convention. Where the upstream map has no entry, the filename-derived
  key is used and the count is recorded as provenance.
- Temperature scaling and every confidence threshold are fitted on **validation
  only**.

Leaf grouping matters because leaves repeat: **41,205 distinct leaf identifiers
across 43,596 official train images** means many images capture the same physical
leaf. Splitting by image would scatter near-identical leaves across the boundary.

## Leakage audit — measured, not assumed

The dataset card claims the splits "preserve the leaf grouping logic (ensuring
images of the same leaf do not appear in both sets)".

**Auditing that claim found it does not fully hold.** Measured on the official
split for the 12 classes:

| Check | Measured |
|---|---|
| Cross-split leaf overlaps (official split) | **5 leaf identifiers** between train and test |
| Examples | `gh_hl leaf 220`, `gh_hl leaf 466.1`, `ghlb2 leaf 8999` |
| Test & train overlap | 5 leaves |
| Test & validation overlap | 0 |
| Train & validation overlap | 0 |
| Leaf identifiers spanning multiple classes | 0 |
| `copy`-suffixed leaves (near-duplicate risk) | 1,207 |
| Cross-split **path** overlaps | 0 |

### Resolution: the `leak_free` policy

The default `split_policy: leak_free` keeps the official test set **untouched**
and drops the 5 implicated leaves from train/validation (5 images removed). The
resulting audit passes with zero cross-split leaf or path overlap, and the number
of dropped images is recorded in the manifest rather than hidden.

Set `split_policy: official` in `configs/dataset.yaml` to reproduce the upstream
boundary and observe the small resulting inflation.

## Acquisition — how images were obtained without the 2.18 GB download

Because the payload is one zip, the project reads **individual members via HTTP
range requests** using a persistent (keep-alive) connection.

Measured on this machine:

| Quantity | Measured |
|---|---|
| Archive size | 2,184,723,441 bytes (2.0 GiB) |
| Range requests honoured | yes |
| Bytes to list the central directory | ~26.7 MB in 4 requests |
| Bytes to acquire 240 sample images | 28.9 MB in 169 requests |
| Full 2,037-image stratified acquisition | **38 MB, 169 seconds** |

That is roughly a **57× reduction** in transferred data versus the full archive.

A connection-reuse fix mattered a great deal: an initial implementation opened a
new TLS connection per request and managed ~15 images/min; reusing one connection
raised it to **~644 images/min** (~40×), completing the acquisition in under three
minutes.

The extraction report is committed at
[`artifacts/reports/extraction.json`](artifacts/reports/extraction.json). If
range reads were ever unavailable, `fieldlens` reports that explicitly and falls
back to a single guarded full download rather than silently switching datasets.

## Acquisition caps (disclosed)

The committed metrics were produced from a **capped** acquisition:

| Split | Acquired | In manifest |
|---|---|---|
| train | 720 | 8,942 |
| validation | 625 | 1,104 |
| test | **692** | **2,454** |

The cap exists to keep the transfer small and the run reproducible on a slow
connection. Re-run without `--per-class-per-split` for the full split; the
evaluation report records the evaluated fraction (28.2% of the test list) so the
smaller evaluation cannot be mistaken for a complete one.
